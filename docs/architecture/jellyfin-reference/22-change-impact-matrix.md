# Change-impact matrix

## Reference boundary

This chapter turns the stock Jellyfin `10.11.11` architecture into a pre-change impact map for the current PiggieTV Web/embedded Plugin worktree. It is not a record of runtime acceptance.

- `W@35c0793` = pristine Jellyfin Web `10.11.11`, official commit `35c0793ece3adbd247eab290ae1effab851f3d37`.
- `S@1fbd873` = pristine Jellyfin Server `10.11.11`, official commit `1fbd8739292cce610231be93daf43368733edf63`.
- `PTV-WEB@0e9c628` = current PiggieTV worktree inspected on `2026-09-04`, base HEAD `0e9c6284c91003fc64bbe02bf675f1ff6ffd9337`, `ptv-version.json` `0.5.57`. The worktree is dirty, so file/symbol/line citations—not the base commit alone—identify current behavior.
- `PTV-PLUGIN@worktree` = embedded Plugin source in that same dirty worktree. Its deployed/runtime state is outside this source-only chapter.

Labels have their atlas-wide meanings: `VERIFIED_FROM_SOURCE`, `VERIFIED_BY_TEST`, `INFERRED`, and `UNKNOWN`. Entries in the general “required proof” columns remain recommendations; the named stabilization updates below separately identify tests that were actually executed and passed.

## How to use the matrix

1. Find every row touched by the proposed change, including indirect rows.
2. Write down the authority, cache key/security scope, lifecycle owner, and terminal state before editing.
3. Execute every required focused and boundary test in the affected rows.
4. Treat a successful HTTP response, render, or build as only the proof named in that row—not proof for adjacent owners.
5. If the relevant authority or invalidator is not established, record `UNKNOWN` and stop before changing production behavior.

The cross-row coupling is `INFERRED` from the source ownership edges in [01-system-overview](01-system-overview.md) and the citations below; the individual owners and behaviors are `VERIFIED_FROM_SOURCE`.

## Issue #38 Music album-query impact — local candidate

The changed owner is the PTV Music album-track loader, not the Jellyfin music entity or PTV playback queue. A user-scoped album item read and a paged Music-library-scoped album search prove the requested album's identity and visibility before track queries. Recursive album children cover nested disc folders; the existing `AlbumIds` relationship covers tracks returned through that relation. Exact `Audio.AlbumId` matching, item-ID deduplication, disc/track ordering, bounded pagination, and route/identity retirement constrain the combined projection. An `Ids` and `ParentId` query is not valid membership proof under the observed Jellyfin 12.2 behavior.

Directly affected surfaces are album count, track rows and their Play/Shuffle queue input. Required focused proof includes flat and nested albums, mixed and foreign album items, another-library and restricted-user rejection, more than one page, incomplete-page failure, and route/server/user cancellation. Boundary proof must confirm IDs, `UserData`, media sources, Now Playing, and playback reporting are unchanged. Authenticated hosted and physical acceptance remain pending; passing local fixtures alone does not close Issue #38.
